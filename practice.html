AWS AI Practitioner (AIF-C01) 实战备考指南

基于 504 题真题提炼 | 每个知识点 = 概念说明 + 真题演练 + 解题套路 💡 学习方法: 先看概念（30秒），再做例题（1分钟），最后记住解题套路（关键词→答案）

一、Bedrock 全家桶（考题占比 ~25%，最重要！）

1.1 Amazon Bedrock — 基础模型托管平台

30秒概念: Bedrock = AWS 的"大模型商店"。提供 Claude、Titan、Llama 等多家 FM，你通过 API 调用就行，不用自己训练或管服务器。

📝 真题演练

【Q34】公司如何在亚马逊 Bedrock 上安全地使用大型语言模型（LLM）？

A. 将 LLM 代码部署在公共仓库中B. 将所有数据以纯文本形式存储在 Amazon S3 上✅ C. 使用最小权限访问原则配置 AWS IAM 角色和策略D. 允许组织中所有成员不受限制地访问亚马逊 Bedrock

💡 解题思路: 看到"安全使用 Bedrock"→ 直接选 IAM 最小权限。Bedrock 安全三板斧：IAM 控权限 + VPC 限网络 + KMS 管加密。

【Q45】一家电子商务公司想要构建一个解决方案，根据客户对产品的书面评价来确定客户的感受。哪些 AWS 服务符合这些要求？（选择两项。）

A. Amazon LexB. Amazon ComprehendC. Amazon Translate✅ D. Amazon BedrockE. Amazon SageMaker Ground Truth

正确答案: B, D

💡 解题思路: "根据评价确定感受" = 情感分析。能做情感分析的：① Comprehend（专业 NLP 服务）② Bedrock FM（通用大模型也能做）。Lex 是聊天框架，Translate 是翻译，Ground Truth 是标注——都不对。

🎯 Bedrock 解题套路

题目关键词 答案
"构建聊天机器人/文本生成/问答系统" Bedrock
"安全使用 Bedrock" IAM 最小权限 + VPC
"审计谁调了 Bedrock" CloudTrail
"在多个 FM 中选择最合适的" Bedrock（多模型可选）
"不想管基础设施 + 用大模型" Bedrock（全托管）

1.2 Bedrock Knowledge Bases / RAG — 私有数据增强

30秒概念: 你的 FM 不知道你公司的数据。Knowledge Bases 把你的文档（PDF、网页等）切块→向量化→存起来。用户提问时，先检索相关文档片段，再交给 FM 生成回答。这就是 RAG（检索增强生成）。

📝 真题演练

【Q46】一家公司希望利用亚马逊 Bedrock 平台上的大型语言模型（LLM）为公司的产品手册开发一个聊天界面。这些手册以 PDF 文件的形式存储。哪种解决方案能以最经济高效的方式满足这些要求？

A. 用产品手册内容微调亚马逊 Bedrock 上的 LLMB. 向亚马逊 Bedrock 上的LLM 提供关于产品手册数据的提示上下文C. 在亚马逊 SageMaker 上训练一个自定义模型✅ D. 将 PDF 文档上传至亚马逊 Bedrock 知识库。当用户提交提示时，使用该知识库提供上下文响应

💡 解题思路: 三个关键词：① "PDF 产品手册"（有现成文档）② "聊天界面"（问答系统）③ "最经济高效"（成本敏感）。微调太贵，自定义训练更贵。直接把 PDF 扔进 Knowledge Bases 做 RAG，零训练成本。

【Q139】一家公司的大型语言模型（LLM）出现了幻觉。公司怎样才能减少幻觉？

A. 增加输入的 token 数量B. 微调模型✅ C. 使用检索增强生成（RAG）D. 增加大型语言模型（LLM）的温度

💡 解题思路: "减少幻觉"四个字→ 直接选 RAG。RAG 让模型基于检索到的真实文档回答，不再自己编造。增加温度反而会增加随机性（更多幻觉）。微调有一定效果但不如 RAG 直接。

🎯 Knowledge Bases / RAG 解题套路

题目关键词 答案
"用公司/私有数据回答问题" Knowledge Bases / RAG
"最经济高效 + 企业文档问答" RAG（不需要微调）
"减少幻觉" RAG（最有效手段）
"知识频繁更新/变化" RAG（更新数据源即可，不用重新训练）
"分块(chunking)的目的" 将文档拆成小片段方便检索

1.3 Bedrock Guardrails — 内容安全护栏

30秒概念: Guardrails = FM 的"安检门"。在输入端和输出端同时设置过滤规则：拦截有害内容、屏蔽 PII、限制讨论话题。

📝 真题演练

【Q54】一家公司想要为儿童开发一款互动应用程序，该程序能基于经典故事生成新的故事。该公司希望使用亚马逊 Bedrock，并且需要确保生成的结果和主题适合儿童。哪种 AWS 服务或功能能满足这些要求？

A. Amazon RekognitionB. 亚马逊 Bedrock 中的自动模型评估✅ C. 亚马逊 Bedrock 的防护栏D. 亚马逊 SageMaker Clarify

💡 解题思路: "确保内容适合儿童" = 内容过滤 → Guardrails。Rekognition 管图片不管文本，Clarify 管偏差不管内容安全。

【Q67】一家医疗公司在亚马逊 Bedrock 上部署了一个疾病检测模型。为遵守隐私政策，该公司希望防止模型在响应中包含患者的个人信息。同时，该公司还希望在出现政策违规情况时收到通知。哪种解决方案能满足这些要求？

A. 使用 Amazon Comprehend 的 PII 检测功能B. 手动审核所有输出✅ C. 使用亚马逊 Bedrock 的防护栏来过滤内容。设置亚马逊 CloudWatch 警报以通知策略违规D. 限制用户的输入内容

💡 解题思路: 两个需求：① 屏蔽 PII → Guardrails ② 违规通知 → CloudWatch 告警。这是经典组合题：Guardrails 过滤 + CloudWatch 告警。

🎯 Guardrails 解题套路

题目关键词 答案
"确保内容适合XX/适龄" Guardrails 内容过滤
"防止泄露个人信息/PII" Guardrails PII 屏蔽
"过滤政治/不当观点" Guardrails 话题限制
"负责任的 AI + Bedrock" Guardrails
"违规时收到通知" Guardrails + CloudWatch 告警

1.4 Bedrock Agents — 任务自动化代理

30秒概念: Agent = 能"动手干活"的 AI。普通 FM 只能回答问题；Agent 能理解请求 → 拆解步骤 → 调用外部 API → 返回结果。

📝 真题演练

【Q305】一家公司想要开发一个 AI 助手来回答用户的查询。该 AI 助手必须评估特定的数据源，查询外部 API，生成回答选项，并对回答选项进行比较和优先级排序。亚马逊 Bedrock 的哪项功能或资源能满足这些要求？

A. 护栏✅ B. 代理C. 知识库D. 自定义模型

💡 解题思路: 看到 "查询外部 API" + "多步骤操作" → 一定是 Agent。Knowledge Bases 只能检索文档，不能调 API。Guardrails 只管过滤，不能执行操作。

🎯 Agents 解题套路

题目关键词 答案
"调用 API / 执行操作 / 完成交易" Agents
"多步骤工作流编排" Agents
"查订单→退款→发通知" Agents
"Agents 的优势是什么" 自动化重复任务 + 编排复杂工作流

二、SageMaker 全家桶（考题占比 ~18%）

2.1 SageMaker 推理模式（四选一，必考！）

30秒概念: 模型训练好了，怎么提供服务？SageMaker 提供 4 种推理模式：

模式 延迟 适合场景 记忆关键词
实时推理 毫秒级 在线应用，低延迟 "实时""毫秒"
无服务器推理 秒级 流量不稳定，不想管服务器 "无需管基础设施"
异步推理 分钟级 大输入(≤1GB)，长处理 "大数据""1GB""排队"
批量转换 小时级 离线批处理整个数据集 "离线""批量""整个数据集"

📝 真题演练

【Q6】一家公司在生产环境中使用亚马逊 SageMaker 来运行其机器学习流程。该公司处理的数据量大，单个数据集可达 1GB，处理时间长达 1 小时，但其需要近乎实时的响应延迟。哪种 SageMaker 推理选项符合这些要求？

A. 实时推理B. 无服务器推理✅ C. 异步推理D. 批量转换

💡 解题思路: "1GB 大数据" + "1小时处理" + "近乎实时" → 异步推理。实时推理处理不了这么大的输入；批量转换是完全离线的，不是"近乎实时"。

【Q27】一家公司需要托管模型并提供预测服务，同时无需管理任何底层基础设施。哪种解决方案能满足这些要求？

✅ A. 使用 Amazon SageMaker 无服务器推理来部署模型B. 使用 Amazon EC2 实例部署模型C. 使用 AWS Lambda 部署模型D. 使用亚马逊 SageMaker 批量转换功能

💡 解题思路: "无需管理基础设施" → 无服务器推理。EC2 需要你管实例，Lambda 有大小限制。

2.2 SageMaker Clarify — 偏差检测 + 可解释性

30秒概念: Clarify 做两件事：① 检测模型是否对某些群体不公平（偏差）② 用 SHAP 值解释模型为什么做出某个预测（可解释性）。

📝 真题演练

【Q101】一家公司正在开发一个机器学习模型来批准贷款。该公司必须实施一个解决方案来检测模型中的偏差。该公司还必须能够解释模型的预测结果。哪种解决方案能满足这些要求？

A. Amazon RekognitionB. Amazon Translate✅ C. 亚马逊 SageMaker ClarifyD. AWS Lambda

💡 解题思路: "检测偏差" + "解释预测" = Clarify 的两大功能，一步到位。

【Q43】亚马逊 SageMaker Clarify 提供了哪些功能？

A. 在生产环境中自动扩展模型B. 自动超参数调整C. 数据加密和安全存储✅ D. 在数据准备过程中识别潜在偏差

💡 解题思路: Clarify = 偏差 + 可解释性。注意它能在"数据准备阶段"（训练前）就检测偏差，不只是训练后。

🎯 Clarify 解题套路

题目关键词 答案
"检测偏差/公平性" Clarify
"解释模型预测/SHAP" Clarify
"贷款/招聘 + 公平" Clarify
"监管要求 + 可解释性" Clarify

2.3 SageMaker Ground Truth — 数据标注

30秒概念: 训练模型需要带标签的数据。Ground Truth 提供标注界面 + 标注团队。Ground Truth Plus = 全托管标注服务（你不用管人）。

📝 真题演练

【Q265】一家公司希望利用人工反馈来微调基础模型（FM），从而对训练数据集进行标注，但该公司不想开发标注应用程序或管理标注人员团队。哪个 AWS 服务或功能符合这些要求？

💡 解题思路: "标注" + "不想管标注团队" → Ground Truth Plus（全托管）。普通 Ground Truth 需要你自己管标注人员。

📝 真题演练

2.5 SageMaker JumpStart — 预训练模型库

📝 真题演练

【Q334】一位人工智能从业者必须对一个开源的大语言模型（LLM）进行微调，以用于文本分类。数据集已经准备好了。哪种解决方案能以最少的操作努力满足这些要求？

A. 在 Amazon Bedrock 上微调模型✅ B. 使用 Amazon SageMaker JumpStart 创建训练任务C. 在 Amazon EC2 上从头训练模型D. 使用 Amazon Comprehend 进行分类

💡 解题思路: "开源 LLM" + "微调" + "最少操作" → JumpStart。Bedrock 上的模型是商业模型不是开源的；EC2 从头搞太麻烦。

2.6 SageMaker Model Cards — 模型审计文档

30秒概念: Model Cards = 模型的"身份证"。记录模型的用途、训练数据、性能指标、局限性，供审计和合规使用。

📝 真题演练

【Q91】一个 ML 研究团队开发定制的 ML 模型。模型成果与其他团队共享。该 ML 团队保留模型训练代码，但需要帮助来记录模型的运行性能以及预期用途。哪种解决方案能满足这些要求？

A. 使用 Amazon CloudWatchB. 使用 SageMaker Clarify✅ C. 使用预期用途以及训练和推理详情创建 Amazon SageMaker 模型卡片D. 使用 AWS CloudTrail

💡 解题思路: "记录模型性能和用途" + "共享给其他团队" → Model Cards。CloudWatch 是监控指标，CloudTrail 是 API 日志——都不是"文档记录"。

📝 Macie — 发现 S3 中的敏感数据

【Q142】一家公司希望将客户服务电子邮件上传至亚马逊 S3。这些邮件有时会包含敏感信息。该公司希望每次发现敏感信息时都能收到警报。哪种解决方案能实现敏感信息检测的完全自动化？

💡 解题思路: "S3" + "敏感信息" + "自动检测" → Macie。Guardrails 过滤 FM 输出，不扫描 S3；Comprehend 做 NLP 分析，不扫描存储。记住：S3 里找 PII = Macie。

📝 CloudTrail — API 审计日志

【Q373】一家公司必须记录每个 AI 从业者在 AWS 账户中所采取的操作。哪种 AWS 服务能满足这些要求？

A. Amazon CloudWatchB. Amazon SageMaker Model Monitor✅ C. AWS CloudTrailD. Amazon Macie

💡 解题思路: "记录操作" = 审计日志 → CloudTrail。CloudWatch 是监控性能指标（CPU、延迟等），不记录"谁做了什么"。

四、核心概念 + 真题

4.1 微调 vs RAG vs Prompt Engineering（出现率最高！）

记住这张决策表，能解决 30%+ 的题：

需求 选
只需控制输出长度/语言/风格 Prompt Engineering
需要引用最新/私有数据 RAG
数据频繁变化 RAG
需要理解专业领域术语 Fine-tuning
有标注数据集要提升特定任务 Fine-tuning
成本敏感 Prompt → RAG → Fine-tuning
减少幻觉 RAG

成本排序（必记！）: Prompt Engineering < RAG < Fine-tuning

📝 真题演练

【Q5】一家公司需要该语言模型的输出简短，并且使用特定的语言。哪种解决方案能使大语言模型的响应质量符合公司的期望？

✅ A. 调整提示B. 选择一个不同规模的大型语言模型C. 升高温度D. 提高 Top K 的值

💡 "输出简短" + "特定语言" = 控制格式/风格 → Prompt Engineering

【Q64】该聊天机器人从研究论文数据库中搜索答案。经过多次提示工程尝试，FM 由于复杂的科学术语表现不佳。公司如何提升表现？

A. 增加 FM 温度B. 使用更大的 FM✅ C. 利用领域自适应微调将 FM 适配到复杂的科学术语上D. 增加更多的提示示例

💡 "提示工程已尝试但不够" + "复杂科学术语" → 需要 Fine-tuning（让模型理解领域语言）

【Q98】一家公司希望部署聊天机器人，为客服提供实时上下文回应。使用公司政策作为知识库。哪种方案最经济高效？

A. 使用微调后的 LLM✅ B. 实现检索增强生成（RAG）提供上下文响应C. 使用 Amazon Lex 构建D. 从头训练自定义模型

💡 "公司政策作为知识库" + "最经济高效" → RAG。微调成本高，且政策更新需重新训练。

4.2 LLM 推理参数

参数 低值效果 高值效果
Temperature 确定、一致、重复（适合事实问答） 创意、多样、随机（适合写诗/故事）
Top-K 只从最高概率几个词选 → 更确定 候选词多 → 更多样
Top-P 只选概率最高的一小部分 → 更确定 选更大概率范围 → 更多样

记忆口诀: 温度低 = 冷静理性; 温度高 = 热情奔放

📝 真题演练

【Q65】一家公司希望在 Bedrock 上使用 LLM 进行情感分析。该公司需要该 LLM 对相同的输入提示给出一致且确定的响应。人工智能从业者应该如何配置推理参数？

✅ A. 将温度设为 0B. 将温度设为 1C. 将 Top-K 设为较大值D. 禁用 Top-P 采样

💡 "一致且确定" → 温度 = 0（完全确定性输出，没有随机性）

4.3 过拟合 vs 欠拟合

过拟合 欠拟合
症状 训练集好，测试集差 训练和测试都差
原因 模型"背答案"了 模型太简单
解决 增加数据、正则化、Dropout 增加模型复杂度、增加特征

【Q44】一家公司正在开发一种新模型来预测特定商品的价格。该模型在训练数据集上表现良好。但投入生产后性能大幅下降。公司应该怎么办？

A. 减少训练数据量B. 向模型添加超参数✅ C. 增加训练数据量D. 增加模型训练时间

4.4 评估指标

分类任务关键指标

指标 一句话 什么时候用
准确率 答对了多少 数据均衡时
精确率 说是的里面真有多少 不能误报（垃圾邮件分类）
召回率 真是的里面找到多少 不能漏报（癌症检测）
F1 精确率和召回率的平衡 两者都重要时
AUC-ROC 综合各阈值的表现 评估分类器整体能力

A. 决定系数（R² 分数）✅ B. 准确性C. 均方根误差（RMSE）D. 学习率

💡 "正确分类了多少" = 准确率 (Accuracy)。R² 和 RMSE 是回归指标，学习率是训练参数不是评估指标。

4.5 嵌入 (Embedding) 与向量数据库

30秒概念: 嵌入 = 把文字/图片变成一串数字（向量）。语义相近的内容，向量距离更近。RAG 就是靠嵌入来"找到相关文档"的。

4.7 幻觉 (Hallucination)

30秒概念: FM 编造看起来合理但实际错误的内容 = 幻觉。

缓解手段（按效果排序）:

  1. RAG — 最有效，基于真实文档回答
  2. Guardrails Grounding Check — 验证输出是否基于参考资料
  3. Prompt 指令 — "只根据提供的信息回答"
  4. 降低温度 — 减少随机性
  5. 人工审核 (A2I) — 关键输出交给人审查

七、考前 30 分钟速记

✅ 10 个必记结论

  1. 成本排序: Prompt < RAG < Fine-tuning
  2. 减少幻觉: RAG 最有效
  3. 偏差检测: SageMaker Clarify
  4. 内容过滤: Bedrock Guardrails
  5. S3 找 PII: Amazon Macie
  6. API 审计: AWS CloudTrail
  7. 性能监控: Amazon CloudWatch
  8. 无代码 ML: SageMaker Canvas
  9. 数据标注: SageMaker Ground Truth（Plus = 全托管）
  10. 模型审计记录: SageMaker Model Cards

✅ 5 个易错陷阱

  1. Rekognition 只管图像/视频 — 文本分析用 Comprehend，不要选错
  2. 温度高 ≠ 更好 — 事实问答/一致性需求要低温度
  3. Lex ≠ 完整聊天机器人 — Lex 是对话框架，需要配合 FM 使用
  4. Clarify 不只管偏差 — 还做可解释性分析（SHAP）
  5. Fine-tuning 需要标注数据，持续预训练不需要 — 这是最常混淆的
