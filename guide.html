AWS AI Practitioner (AIF-C01) 备考指南

基于 504 题真题题库提炼，覆盖 44 个 AWS 工具 + 50+ 个核心概念

第一部分：AWS AI 工具大全

按考试重要性分四个梯队。每个工具写清楚：是什么 → 干什么用 → 考试怎么考

🔴 第一梯队：Bedrock 生态（考题占比 ~25%）

1. Amazon Bedrock ⭐⭐⭐⭐⭐ (120题)

是什么: AWS 的托管基础模型(FM)平台。你不需要自己训练大模型，Bedrock 提供了多家公司的现成大模型（Claude、Titan、Llama、Mistral 等），通过 API 直接调用。

核心能力:

  • 调用多种基础模型（FM），按 token 付费
  • 支持对模型做微调（Fine-tuning）
  • 提供模型评估功能（自动/人工评估）
  • 配合 Knowledge Bases、Guardrails、Agents 构成完整生态

考试怎么考:

  • 🎯 "公司要构建聊天机器人/文本生成/情感分析应用" → Bedrock
  • 🎯 "需要安全调用大模型" → Bedrock + IAM 最小权限 + VPC 端点
  • 🎯 "在多个 FM 之间选择" → Bedrock 提供多模型对比能力
  • 🎯 "公司不想自建基础设施" → Bedrock 是全托管的

2. Bedrock Knowledge Bases（知识库）⭐⭐⭐⭐ (22题)

是什么: Bedrock 的RAG 组件。把你的私有文档（PDF、网页、数据库）自动向量化存储，让 FM 能检索并引用你的数据来回答问题。

核心能力:

  • 连接 S3 数据源，自动分块(chunking) + 向量化(embedding)
  • 查询时自动检索相关文档片段，注入到 FM 的上下文中
  • 支持多种向量数据库后端（OpenSearch、Pinecone 等）

考试怎么考:

  • 🎯 "用公司私有数据回答问题" → Knowledge Bases / RAG
  • 🎯 "最经济高效的方式让 FM 引用企业文档" → Knowledge Bases（不需要微调）
  • 🎯 "减少 FM 幻觉" → RAG 让模型基于真实文档回答
  • 🎯 "知识频繁更新" → RAG（微调需要重新训练，RAG 只需更新数据源）

3. Bedrock Guardrails（护栏/防护机制）⭐⭐⭐⭐ (23题)

是什么: Bedrock 的内容安全过滤层。在 FM 的输入和输出两端设置过滤规则，拦截不合规的内容。

核心能力:

  • 内容过滤: 拦截暴力、仇恨、性相关、侮辱性内容（按严重程度可调阈值）
  • PII 屏蔽: 自动检测并屏蔽姓名、电话、邮箱、身份证号等个人信息
  • 话题限制: 禁止模型讨论特定话题（如政治、竞品）
  • 上下文接地检查 (Grounding Check): 验证模型回答是否基于提供的参考材料

考试怎么考:

  • 🎯 "确保生成内容适合儿童" → Guardrails 内容过滤
  • 🎯 "防止模型泄露患者个人信息" → Guardrails PII 屏蔽
  • 🎯 "过滤政治偏见内容" → Guardrails 话题限制
  • 🎯 "确保负责任的 AI" → Guardrails
  • 🎯 "出现违规时收到通知" → Guardrails + CloudWatch 告警

4. Bedrock Agents（代理）⭐⭐⭐ (24题)

是什么: Bedrock 的任务自动化引擎。让 FM 不只是回答问题，还能主动调用外部 API、查询数据库、执行多步骤工作流。

核心能力:

  • 理解用户请求 → 拆解成步骤 → 依次调用 API → 汇总结果
  • 可以连接 Knowledge Bases 获取知识
  • 支持 Lambda 函数作为 Action Group

考试怎么考:

  • 🎯 "AI 助手需要查 API、执行操作、完成交易" → Bedrock Agents
  • 🎯 "编排复杂工作流 + 知识检索" → Agents + Knowledge Bases
  • 🎯 "自动化客服流程（查订单→退款→发邮件）" → Agents

🔴 第二梯队：SageMaker 生态（考题占比 ~18%）

5. Amazon SageMaker ⭐⭐⭐⭐⭐ (70题)

是什么: AWS 的端到端机器学习平台。从数据准备、模型训练、调优、部署到监控，一站式搞定。

核心能力:

  • 训练: 内置 17+ 算法，也支持自定义算法/框架
  • 推理（4种模式，必考！）:- 实时推理 (Real-time): 毫秒级延迟，持续在线端点 → 适合在线应用
  • 无服务器推理 (Serverless): 自动扩缩，无需管基础设施 → 适合流量不稳定
  • 异步推理 (Async): 处理大输入（最大 1GB），排队处理 → 适合大文件/长任务
  • 批量转换 (Batch Transform): 离线批处理整个数据集 → 适合批量预测
  • Notebook: SageMaker Studio 提供 Jupyter 开发环境

考试怎么考:

  • 🎯 "构建/训练/部署 ML 模型" → SageMaker
  • 🎯 "近实时响应 + 大数据输入 + 长处理时间" → 异步推理
  • 🎯 "无需管基础设施" → 无服务器推理
  • 🎯 "离线批量处理" → 批量转换
  • 🎯 "低延迟在线预测" → 实时推理

6. SageMaker Clarify ⭐⭐⭐⭐ (23题)

是什么: SageMaker 的偏差检测 + 可解释性分析工具。

核心能力:

  • 偏差检测: 分析训练数据和模型预测是否对特定群体不公平
  • 特征重要性: 用 SHAP 值解释哪些特征最影响模型预测
  • 模型可解释性报告: 生成报告供监管审计

考试怎么考:

  • 🎯 "检测模型偏差/公平性" → Clarify
  • 🎯 "解释模型为什么做出这个预测" → Clarify (SHAP)
  • 🎯 "满足监管可解释性要求" → Clarify
  • 🎯 "在训练前检测数据偏差" → Clarify

7. SageMaker Ground Truth ⭐⭐⭐ (12题)

是什么: AWS 的数据标注服务。为训练数据打标签（如图片分类标签、文本情感标签）。

核心能力:

  • 内置标注界面（图像、文本、视频）
  • 支持人工标注 + 自动标注结合（active learning）
  • Ground Truth Plus: 托管标注团队，你不需要管标注人员

考试怎么考:

  • 🎯 "需要标注训练数据" → Ground Truth
  • 🎯 "不想自己管标注团队" → Ground Truth Plus
  • 🎯 "用人工反馈微调 FM (RLHF)" → Ground Truth

8. SageMaker JumpStart ⭐⭐⭐ (9题)

是什么: SageMaker 的预训练模型市场。提供 300+ 开源预训练模型，一键部署或微调。

考试怎么考:

  • 🎯 "快速部署开源 FM" → JumpStart
  • 🎯 "在 VPC 内部署 FM" → JumpStart（区别于 Bedrock 在 AWS 托管）
  • 🎯 "控制员工对 FM 的访问" → JumpStart + IAM

9. SageMaker Canvas ⭐⭐⭐ (8题)

是什么: SageMaker 的无代码 ML 工具。面向非技术人员，拖拽式建模。

考试怎么考:

  • 🎯 "没有编程经验" + "需要建 ML 模型" → Canvas
  • 🎯 "业务用户做需求预测/员工流失预测" → Canvas

10. SageMaker Model Cards ⭐⭐ (17题)

是什么: 模型的文档记录卡片。记录模型的用途、训练数据、性能指标、限制条件等元信息，用于审计和合规。

考试怎么考:

  • 🎯 "为审计目的记录模型信息" → Model Cards
  • 🎯 "记录模型训练和性能详情" → Model Cards

第二部分：AI/ML 核心概念

A. 机器学习三大范式

范式 定义 数据要求 典型应用
监督学习 用带标签的数据训练 需要大量标注数据 分类（垃圾邮件检测）、回归（房价预测）
无监督学习 用无标签的数据，发现隐藏模式 不需要标注 聚类（客户分群）、异常检测、降维
强化学习 通过试错和奖励学习最优策略 环境反馈信号 游戏AI、机器人、自动驾驶、DeepRacer

半监督学习: 少量标注 + 大量未标注 → 结合两者优势

B. 模型评估指标（高频！）

分类任务指标

指标 公式 什么时候用
准确率 (Accuracy) 正确预测数 / 总数 数据均衡时的总体表现
精确率 (Precision) TP / (TP+FP) 关注"预测为正的里有多少真的是正"（如垃圾邮件检测：减少误判正常邮件）
召回率 (Recall) TP / (TP+FN) 关注"真正为正的有多少被找到"（如癌症检测：不能漏诊）
F1 分数 精确率和召回率的调和平均 需要平衡精确率和召回率
AUC-ROC ROC 曲线下面积 评估分类器在各阈值下的综合表现

回归任务指标

指标 说明
RMSE (均方根误差) 预测值与真实值的平均偏差，越小越好
R² (决定系数) 模型解释了多少数据变异，越接近 1 越好

混淆矩阵

                  预测为正    预测为负
实际为正          TP (真正)   FN (漏报)
实际为负          FP (误报)   TN (真负)

C. 过拟合 vs 欠拟合

过拟合 (Overfitting) 欠拟合 (Underfitting)
症状 训练集表现好，测试集表现差 训练集和测试集表现都差
原因 模型太复杂，"背答案"了 模型太简单，学不到规律
解决 增加数据、正则化、Dropout、早停、交叉验证 增加模型复杂度、增加特征、减少正则化

D. 微调 vs RAG vs Prompt Engineering（最高频对比！）

Prompt Engineering RAG Fine-tuning
原理 只改输入提示词 检索外部文档注入上下文 修改模型参数
成本 💰 最低 💰💰 中等 💰💰💰 最高
适用场景 控制输出格式/语言/风格 需要最新/私有数据 需要领域专业术语/改变模型行为
数据需求 不需要 需要文档库 需要高质量标注数据
知识更新 即时 更新文档即可 需要重新训练
减少幻觉 ❌ 有限 ✅ 有效（基于真实文档） ⚠️ 一定程度

🎯 考试决策树

问: 需要改进 FM 表现？
├── 只需控制输出长度/语言/风格？ → Prompt Engineering
├── 需要引用最新/私有数据？ → RAG
├── 数据频繁变化？ → RAG
├── 需要理解专业领域术语？ → Fine-tuning
├── 成本敏感？ → Prompt → RAG → Fine-tuning（按成本递增尝试）
└── 改变模型的核心行为？ → Fine-tuning

成本效益排序（考试必记）: Prompt Engineering > RAG > Fine-tuning

E. Prompt Engineering 技术

技术 说明 示例
零样本 (Zero-shot) 不给示例，直接提问 "把以下文本翻译成英文：..."
少样本 (Few-shot) 给几个示例让模型学习格式 "情感: 正面。评价: 很棒... / 情感: 负面。评价: 太差..."
思维链 (Chain-of-Thought) 引导模型逐步推理 "请一步一步思考这个问题..."
系统提示 (System Prompt) 设定模型的角色和行为规则 "你是一个专业的法律顾问，只用中文回答"
上下文学习 (In-context Learning) 在提示中提供背景信息 把相关文档内容塞进提示

F. LLM 推理参数

参数 作用 值低 值高
Temperature (温度) 控制输出随机性 确定性高、重复性高（适合事实问答） 创造性高、多样性高（适合写诗/故事）
Top-K 只从概率最高的 K 个词中采样 更聚焦、更确定 更多样
Top-P (nucleus) 只从累计概率达 P 的词中采样 更聚焦 更多样
Max Tokens 限制输出长度 短回复 长回复

记忆技巧: 温度低 = 冷静理性 = 确定性答案; 温度高 = 热情奔放 = 创意发散

G. 嵌入 (Embedding) 与向量数据库

嵌入: 把文本/图片转换成数学向量（一串数字），语义相近的内容在向量空间中距离更近。

用途:

  • RAG 中把文档向量化并存入向量数据库
  • 语义搜索：找"意思相近"而非"关键词匹配"的内容
  • 推荐系统：找相似物品

向量数据库: 存储和检索嵌入向量的专用数据库→ AWS 上用 Amazon OpenSearch 的向量搜索功能

H. 幻觉 (Hallucination)

是什么: FM 生成听起来合理但实际错误或编造的内容。

缓解方法:

  1. RAG — 让模型基于真实文档回答（最有效）
  2. Guardrails 接地检查 (Grounding Check) — 验证输出是否基于参考资料
  3. Prompt Engineering — 指示模型"只根据提供的信息回答，不确定时说不知道"
  4. 降低温度 — 减少随机性
  5. 人工审核 (A2I) — 关键输出交给人检查

I. 偏差 (Bias) 与公平性

数据偏差来源:

  • 训练数据不均衡（某类样本过多/过少）
  • 历史数据本身反映了社会偏见
  • 采样偏差（只收集了特定人群的数据）

检测: SageMaker Clarify → 训练前数据偏差检测 + 训练后模型偏差检测

缓解:

  • 使用多样化、平衡的训练数据
  • 数据增强 (Data Augmentation)
  • Clarify 持续监控
  • 人工在环 (Human-in-the-loop) 审核

J. 负责任的 AI 框架

考试常考的负责任 AI 六大支柱:

支柱 含义 AWS 工具
公平性 (Fairness) 模型不歧视特定群体 Clarify
可解释性 (Explainability) 能解释模型决策原因 Clarify (SHAP)
透明度 (Transparency) 公开模型的能力和限制 Model Cards
隐私与安全 保护个人数据 Macie, KMS, Guardrails
可控性 (Controllability) 人类能监督和干预 A2I, Guardrails
治理 (Governance) 有政策、流程、合规保障 CloudTrail, IAM

K. 数据处理关键概念

概念 说明
特征工程 从原始数据中提取/构造对模型有用的变量
数据增强 通过变换（旋转、翻转、噪声）扩充训练数据
合成数据 用算法生成的人工数据（GAN可生成）
数据拆分 训练集(~70%) + 验证集(~15%) + 测试集(~15%)
标注 (Labeling) 为数据打标签（Ground Truth）
数据漂移 生产数据分布偏离训练数据 → Model Monitor 检测
特征存储 统一管理和复用特征变量 → Feature Store

L. 模型优化与部署

技术 说明 效果
模型蒸馏 (Distillation) 大模型教小模型 保持性能，减小体积
模型量化 (Quantization) 降低数值精度（如 FP32→INT8） 减少内存，加速推理
迁移学习 复用预训练模型到新任务 减少训练数据和时间
RLHF 用人类反馈微调模型对齐人类偏好 提升对话质量
持续预训练 用领域数据继续训练基础模型 让模型学习领域知识

第四部分：易混淆对比

🆚 Bedrock vs SageMaker

Bedrock SageMaker
定位 调用现成大模型 (FM) 端到端自建 ML 模型
用户 应用开发者 数据科学家/ML工程师
训练 微调他人的 FM 从头训练或自定义模型
部署 API 调用即可 需要配置端点

🆚 Guardrails vs Comprehend vs Macie

Guardrails Comprehend Macie
过滤对象 FM 的输入/输出 任意文本 S3 中的文件
用途 内容安全+PII屏蔽 NLP分析(情感/实体) 发现敏感数据
场景 实时拦截 离线分析 数据治理

🆚 Kendra vs OpenSearch vs Knowledge Bases

Kendra OpenSearch Knowledge Bases
搜索类型 企业文档搜索 向量搜索 RAG 检索
独立使用 ✅ ✅ ❌ (依赖 Bedrock)
与 FM 结合 可以但需额外集成 作为向量数据库后端 原生集成 Bedrock FM

🆚 Ground Truth vs A2I

Ground Truth A2I
时机 训练前（标注数据） 推理后（审核预测）
目的 给数据打标签 对低置信度预测人工复查

🆚 CloudTrail vs CloudWatch

CloudTrail CloudWatch
记录什么 谁做了什么（API 调用日志） 系统表现如何（指标/日志）
用途 安全审计 性能监控+告警

第五部分：考前速记清单

✅ 10 个必记结论

  1. 成本优先级: Prompt Engineering < RAG < Fine-tuning
  2. 减少幻觉: RAG 是最有效手段
  3. 偏差检测: 用 Clarify
  4. 内容过滤: 用 Guardrails
  5. PII 发现: S3 里用 Macie，FM 输出用 Guardrails
  6. 审计日志: 用 CloudTrail
  7. 无代码 ML: 用 Canvas
  8. 数据标注: 用 Ground Truth
  9. 私有部署: VPC 端点
  10. 模型记录: Model Cards

✅ 5 个易错陷阱

  1. Rekognition 常做干扰项 — 图像分析用它，但不能做文本分析
  2. Lex 不等于聊天机器人 — Lex 是对话框架，不含 LLM 能力
  3. 微调不是万能的 — 知识更新快的场景优先用 RAG
  4. 温度高 ≠ 更好 — 事实问答要低温度
  5. Clarify 不只检测偏差 — 它也做可解释性分析（SHAP值）
